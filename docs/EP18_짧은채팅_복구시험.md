# EP18 짧은 채팅 복구 시험

새 제작 채팅의 첫 요청으로 아래 문구를 사용한다. 현재 사용자의 새 채팅 생성 요청이 있을 때만 실행한다.

```text
EP18 농경문 청동기의 기존 파일과 승인 기록을 유지하고, 긴 채팅의 반복 로딩을 피하는 작은 작업 채팅으로 복구 시험한다.
저장소: C:/Users/7500F/Documents/Codex/2026-08-25/https-github-com-jjwwhhjj1116-prog-godeumul/work/Godeumul-ep18-workflow
AGENTS.md와 산출물/EP18_농경문청동기/00.재개카드.md를 읽고, tools/workflow_status.py로 현재 EP18 상태를 한 번 확인한다.
이 첫 시험에서는 로그/전체 대화/영상 폴더를 재귀 검색하지 말고, 새 생성·업로드·기존 파일 변경 없이 실제 단계·차단 원인·재개점을 짧게 보고한다. 첫 상태 조회를 완료하면 멈춘다.
이전 코드 수정은 커밋 24f2653에 있으며 대본·TTS는 보존되어 있다. 005 v4는 유물 형태 FAIL이고 006~021 새 체인은 미접수다. 불합격 v10을 최종본으로 쓰지 않는다.
이 시험 요청은 유료 재시도나 QA 통과 승인을 새로 부여하지 않는다. 시험 이후 제작에는 기존 사용자 승인 범위와 현행 정책을 적용한다.
```

시험 결과는 이 기존 채팅에서 새 채팅 상태를 한 번 읽어 비교한다. 오류 없는 첫 조회만으로 장시간 앱 안정성이 입증된다고 주장하지 않는다.

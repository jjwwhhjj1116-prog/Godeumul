## 재확인한 앱 문제

10월 5일 PID 7620 로그에서 build 13022에서도 다음 현상이 확인됐다.

- 같은 renderer 1에서 app_start가 18:16:29, 18:18:09, 18:36:44에 기록됨.
- ResizeObserver 오류 13회.
- 현재 채팅의 thread/items/list 1,040회. 18:17에는 355회, 18:35에는 196회, 18:36에는 314회가 집중됨.
- 앱 전체 thread_history_page 161회. 이 이벤트에는 채팅 ID가 없어 전부 현재 채팅의 조회라고 단정하지 않음.
- 명시적인 renderer crash/OOM 또는 요청 timeout은 발견하지 못함.

화면 재초기화, 기록 집중 조회, 레이아웃 오류가 함께 재발한 것은 확인했다. 직접적인 원인 코드와 수동/자동 재시작 여부까지 확정하지 못했다. 업데이트만으로 해결됐다는 판단은 하지 않는다.

10월 6일 09시 이후 생성된 로그 세 개는 조사 시점 0바이트였다. 읽을 수 있는 이전 파일의 마지막 시각은 08:56:46이므로 현재 증상의 소멸을 증명하지 않는다. 새벽 03:50:37 DNS 오류는 03:51:03 복구됐으며 어제 저녁 UI 문제와 같은 장애라고 묶지 않는다.

## 발견되지 않은 원인

사용자 TOML과 전역 상태 JSON은 정상 파싱됐다. MCP는 node_repl 하나이며 관련 실행 경로도 존재한다. 프로젝트 등록 36개는 자동시작 36개가 아니다. 전역 대기열은 비어 있고 자동 컨텍스트 첨부도 false다. 설정 파손, 중복 MCP, 바이러스, PC 사양 부족으로 원인을 단정하지 않는다.

격리된 shell에서는 프로세스가 세 개만 보여 실제 PC 부하를 판단할 수 없었다. 별도 읽기 검사로 실제 앱 경로·버전을 확인했다. 프로세스 종료, DB 변경, 브라우저 재설치는 하지 않았다.

## 남은 복구 시험

긴 채팅의 기록 조회 문제를 분리할 작은 새 채팅 시험 문구를 `docs/EP18_짧은채팅_복구시험.md`에 준비했다. 기존 대본·TTS·실제 생성 파일·유료 재시도 한도는 유지된다. 사용자의 새 채팅 생성 선택을 요청한 상태이며 답변 전 생성하지 않는다.

첫 상태 조회가 정상이라고 장기 재로딩 문제가 해결됐다고 선언하지 않는다. 같은 파일로 작은 채팅과 이 채팅을 비교해 재발 범위를 확인한다.

Windows Computer Use 지침은 ChatGPT desktop app UI 자동화를 금지한다. 따라서 그 도구로 앱의 패널·대화 UI를 직접 조작하는 복구는 실행하지 않았다. 이 제한은 파일·설정 읽기와 위 중복 수정에 적용되지 않는다.

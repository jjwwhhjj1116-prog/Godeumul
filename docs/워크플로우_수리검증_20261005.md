# 워크플로우 재검수 후 수정 결과

2026-10-05. 범위: 제작 도구·현행 지침·설치된 CapCut 스킬의 결함 수정.
영상 생성, YouTube 변경, 실행 중 CapCut 편집, 인증 초기화, 앱 재시작은 하지 않았다.

| 썸네일 원격 변경을 완료로 간주 | URL 변경 시 REVIEW_REQUIRED, URL 일치도 픽셀 검증으로 주장하지 않음 | 원격 변경/동일 URL 테스트 |
| 정상 응답 없이 업로드 대기 지속 | 요청 60초, 무진행 180초/전체 1,800초 감시 | 무진행·전체 한도 테스트 |

| 재개 요약이 QA 누락·직접 FAIL을 놓침 | 명시 참조 파일 누락, 상위/장면/경계 FAIL 수집·첫 줄 차단 원인 표시 | 누락/손상/경계 FAIL/옛 실패 이력 제외 테스트 |

업로드 시간 감시는 진행 루프 기준이며 통신 응답 대기 때문에 최대 요청 제한만큼 판정이 늦어질 수 있다. 통신 시간 초과를 무조건 새 업로드로 재시도하지 않는다. 성공 ID가 없으면 접수 불명 기록을 남긴다. 구형 예약 체크포인트에 최초 요청 본문이 없으면 날짜를 추측해 복구하지 않는다.

기존 사용자 CapCut 프로젝트, 대본, TTS, 원본 영상, 토큰은 보존했다. 조립 실패 임시 폴더는 복구용으로 남기며 자동 삭제하지 않는다. 설치 스킬의 이전 사본도 회차 QA 폴더에 보관했다. 다른 채널 스킬과 사용자 `tools/subtitle_split.py` 변경은 수정 대상에서 제외했다.

## 검증 결과

- `python -B -X utf8 -m unittest discover -s tests -p 'test_*.py' -q`: **175개 통과**. 테스트 임시 경로는 저장소 `.test-tmp`.
- 저장소 및 실제 설치 CapCut 스킬 `quick_validate.py`: 통과. 줄바꿈 정규화 후 텍스트 동일.
- `git diff --check`: 통과.
- 실제 EP18 `workflow_status.py --check script`: 대본 검문 PASS, 전체 제작은 **005 유물 형태 FAIL / 006~021 새 체인 미접수**로 표시.
- 실제 EP18 `capcut_build.py --check`: 새 템플릿 오류는 해소. `04Q.대본영상의미검수.json`과 `02G.연속탐방계약.json` 부재 때문에 조립 차단. 이것은 미검수 원본을 통과시키지 않는 정상 동작이다.
- 유료 생성·실제 YouTube 업로드·GUI 전체 재생은 이번 코드 테스트에 포함하지 않았다. 통과 숫자를 완성 영상의 품질이나 실제 제작 시간 개선 측정치로 해석하지 않는다.

## Codex 앱 재로딩은 별도 미해결

이전 로그 재검수에서 화면 재초기화·대화 이력 반복 로딩이 확인됐지만 자동/수동 재시작과 직접 원인은 확정하지 못했다. 제작 스크립트 수정이 앱 내부 렌더러를 고친 것은 아니다. 바이러스·PC 사양·대화 DB 손상으로 단정할 증거도 없다.

원인 분리를 위한 다음 검증은 기존 파일을 유지한 작은 새 채팅에서 같은 읽기 전용 상태 조회를 실행하고 동일 증상 재발 여부를 대조하는 것이다. 새 채팅 생성은 사용자 요청 후에만 한다. 증상이 계속되면 발생 시각과 해당 구간 로그로 앱 피드백을 제출할 수 있다. 로그·쿠키·인증·대화 DB 삭제 또는 전체 앱 강제 종료는 하지 않는다.

# 쇼츠 제작 워크플로 — [고대유물의 비밀]

대본 한 편에서 업로드까지 7단계. **워크플로는 고정이고, 카테고리는 설정 파일
하나로 바꾼다.** 다른 PC에서 이 저장소를 받아 `채널설정.json` 만 갈아끼우면
같은 파이프라인이 다른 채널로 돈다.

현재 채널은 고대 유적·유물의 **숨겨진 공학 메커니즘**을 3D 디오라마 단면으로
해부한다. 신비한 건축사전의 시각 문법(줌인 → 단면 → 분해 → 원리)을 고고공학
주제에 이식한 것이다.

## 카테고리를 바꾸려면

**`채널설정.json` 하나만 고친다. `tools/` 안의 코드는 건드리지 않는다.**

| 항목 | 무엇을 바꾸나 |
|---|---|
| `채널` | 이름, 슬러그, 주제 목록 파일 경로 |
| `tts` | 보이스 ID, speed / stability / similarity / style |
| `자막` | 글꼴, 크기, 획 두께, 세로 위치 |
| `워터마크` | 위치, 크기, 크로마키 색 |
| `해부쿼터` | 컷 타입별 최소 개수. **카테고리 성격에 맞게 조정한다** |
| `썸네일` | 상단 문구, 글꼴, 제목 색 |
| `업로드` | 유튜브 카테고리 ID, 언어, 해시태그 상한 |
| `캡컷` | 템플릿 프로젝트 이름 |

지침 문서(01~07)도 카테고리에 맞게 손본다. 파이프라인 구조는 그대로 두고
**어휘와 예시만** 바꾸면 된다. 특히:

- **01 대본 지침** — 5챕터 구조와 필수 문장을 새 카테고리 말투로
- **02 시각화 지침** — 줌인 해부 체인은 유지, 컷 타입 이름과 예시만 교체
- **06 썸네일** — 배경 프롬프트의 `{{ }}` 자리만 교체

| **3** | **TTS 실측 (먼저!)** | 장면 구분 | `audio/*.mp3` + `durations.json` | [03](./03.TTS생성지침.md) | `tts_generate` → `audio_normalize` |
| **2b** | 프롬프트 생성 | 실측 길이 | 컷별 6대 항목 + 옴니 규격 | [02](./02.시각화+영상화프롬프트(고대유물).txt) | `speed_table.py` |

| **6** | 제목·설명·썸네일 | 완성 영상 | `06.메타.json` + `썸네일.jpg` | [06](./06.제목_설명_썸네일지침.md) | `thumbnail_build.py` |

각 단계는 **파일로만 연결된다.** 앞 단계 산출물이 없으면 다음 단계가 못 돈다.

> ★ **2단계는 TTS를 사이에 두고 둘로 갈라진다.** 옴니 영상 길이를 4/6/8/10초
> 규격에서 골라야 하는데, 그러려면 나레이션 실측 길이를 먼저 알아야 한다.
> 추정치로 정하면 영상을 전부 다시 뽑게 된다.

## 이 채널의 정체성 — 줌인 해부 체인

전부 여기서 나온다. 다른 규칙은 다 이걸 지키기 위한 장치다.

```
L1 EXTERIOR   지상 전경. 유물의 겉모습
L2 APPROACH   접근. 표면 질감이 보이는 거리
L3 CUTAWAY  ★ 지표를 잘라 내부 노출. 절단면에 지층이 보인다
L4 EXPLODED ★ 부품이 공중에서 분해되어 떠 있다
L5 MECHANISM★ 부품 하나에 초근접. 힘이 붉은 화살표로 흐른다
```

- **챕터 4(역발상 솔루션)는 L3 → L4 → L5를 전부 밟아야 한다.**
- 겉모습 컷이 연속 3개를 넘으면 위반이다.
- **카메라는 멈추지 않는다.** STATIC 20% 이하, 관통 컷 4개 이상,
  같은 무빙 2연속 금지. (EP01에서 STATIC 56%로 실패했다 →
  [00.함정목록](./00.함정목록.md) 2-2)

세로(9:16)는 불리한 조건이 아니라 유리한 조건이다. 무덤 수직갱, 우물, 지하
궁전, 피라미드 내부 통로 — 고대유물 주제는 수직 구조가 많다.

## 규칙

1. **크레딧·계정을 쓰는 명령은 기본이 드라이런.** `--run` 없이는 아무 일도 안 난다.
2. **키는 `.env` 에만.** 지침이나 코드에 절대 적지 않는다. 원격에 한 번이라도
   올라가면 히스토리에서 지워도 유출로 보고 재발급한다.
3. **출처를 댈 수 없는 내용은 대본에 넣지 않는다.** 회차마다 `00.팩트체크.md` 를
   쓰고, C등급(문헌만·실물 미확인)이 있으면 설명란에 재현 고지를 넣는다.
   업로더가 이걸 검사해서 없으면 막는다.
4. **내보내기 전에 `verify_draft.py` 를 돌린다.** 영상·나레이션·자막이 같은
   시간축에 놓였는지, 소리가 클리핑하지 않는지 41개 항목을 전수 검사한다.
   실패가 하나라도 있으면 올리지 않는다.
5. **새로 걸린 함정은 [00.함정목록.md](./00.함정목록.md) 에 한 줄 추가하고,
   반드시 코드나 지침에도 박는다.** 표에만 적으면 다음에 또 걸린다.

## 다른 파이프라인과의 관계

- **무협 TTS 파이프라인** (`../TTS+영상 변환기/`)과 같은 ElevenLabs 계정을 쓴다.
  월 한도를 공유하므로 대량 생성 전에 잔여량을 확인할 것.
- 이 채널은 무협 파이프라인 코드를 **건드리지 않는다.** 완전히 별도 폴더,
  별도 스크립트다. 무협 회귀 테스트에 영향이 없다.
- 02단계 지침은 무협 `03E.시각화+영상화프롬프트(무협).txt` v11.1을 이 채널용으로
  개작한 것이다. 워크플로 골격(컷 판정 → 해부 → 프롬프트 → I2V)은 동일하다.

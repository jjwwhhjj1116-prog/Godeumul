# 고대유물 제작 총괄

[현행 제작 정책](../../00.현행제작정책.md)이 모드·진행 범위의 단일 기준이다.
[제작 시작 워크플로](../../00.제작_시작_워크플로우.md)는 단계별 실행과 세부 검수의 기준이다.
사용자의 현재 지시와 기존 명시 승인이 두 문서보다 우선한다.

## 재개

`python -X utf8 -B tools/workflow_status.py EP경로`로 현재 기록과 다음 행동을 확인한다.
요약은 읽기 전용 재개 안내다. 실제 QA가 실행되지 않았다면 VERIFIED라고 보고하지 않는다.
변경 없는 대본·TTS를 다시 생성하지 않고 마지막 검증 결과 다음부터 진행한다.
기존 서비스와 동일 제작 범위는 이미 승인됐으면 단계마다 다시 묻지 않는다.
명시된 추가 비용·재시도 상한 및 게시 승인은 별도로 보존한다.

## 단계별 참고

- 대본: 사용자 제미나이 원고의 사실만 최소 수정. 승인 해시와 `01.문맥검수.json` v3 이후 TTS.
- 장면·영상: `02d.영상생성모드.json`을 먼저 읽고 현행 정책의 해당 모드 문서만 선택.
  EP18 출력 프레임 연쇄에는 사전 N+1 전체 이미지 요구를 적용하지 않는다.
- 고증·연출: `02D`, `02M`, `02E`의 해당 단계 기준. 실제 유물 형태와 문장 속 동작을 함께 보여준다.
  카메라 경로·발견 결과·VEO 설명동작이 실제 생성물에서 보이는지 전체 재생으로 확인.
- Flow: 현재 제공된 Chrome 제어 스킬로 본문 첨부·입력·생성. 확장 배치 TXT/JSON 작성은 실행 완료가 아니다.
- CapCut: `skills/ancient-artifact-capcut-finish/SKILL.md`를 해당 단계에서 읽고 GUI 마감·오디오·전체 재생·4K 내보내기 검수.
- 썸네일: 해당 thumbnail 스킬. 현재 승인 디자인·텍스트를 사용.
- 납품·게시: OneDrive 최종 폴더와 해시 잠금 후 기존 YouTube API/토큰을 사용. 기존 영상 ID를 확인하고 같은 파일의 중복 업로드를 막는다.

## 실행 감독

총괄은 승인된 실제 단계를 이어 실행한다. UI 소유자는 한 명이다.
독립 검수·코드 업무만 병렬로 맡기며 여러 에이전트가 같은 생성 버튼이나 편집 타임라인을 조작하지 않는다.
원격 접수 결과가 불명확하면 기존 결과를 먼저 확인한다. 같은 연결 시험은 최대 두 번이다.
비용 범위를 넘거나 사용자 인증이 필요할 때는 실제 원문 오류와 필요한 행동을 구체적으로 알린다.
원본 전체 재생 QA·프레임 연쇄·대본 의미 검수 없이 PASS 파일을 작성하지 않는다.
진단용 드래프트 복제는 제작 경로가 아니다. 정식 조립기에서 검수한 파일·SHA·사용 구간을 그대로 사용한다.

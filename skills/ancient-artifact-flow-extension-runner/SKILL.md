# Flow 확장 관찰·실행

먼저 저장소 `AGENTS.md`, `00.제작_시작_워크플로우.md`, `02S.디오라마_공통시각기준.md`를 읽는다.
공통 스타일는 `채널설정.json`에서 가져오며 자체 표현으로 대체하지 않는다.

## 관찰 모드

사용자가 시연을 시작하기 전에는 생성 버튼·설정·탭·확장을 변경하지 않는다. Chrome을 제어할
때는 현재 환경의 Chrome 제어 스킬을 먼저 읽는다. 연결이나 녹화가 안 됐으면 준비됐다고 속이지 않는다.

시연 중 기록할 것: 모드 이름, TXT 구분법, 참조 칩, 비율, 기본 길이, 출력 수, 이미지 정렬과
영상 프롬프트 짝짓기, 시작/끝 처리 옵션, 저장 폴더, 실제 다운로드 이름. 화면에 보인 사실과
사용자 설명을 구분한다. 비밀번호·토큰·다른 확장 목록은 수집하지 않는다.

동영상으로 모델을 재훈련한다고 말하지 않는다. 사용자 확인을 거친 재현 가능한 클릭 순서와
선행 조건을 회차 관찰 기록에 남긴다. 모르는 버튼·동작은 추측으로 채우지 않는다.

## 제작 모드

1. 생성 승인이 있을 때만 실행한다. 기존 대본/TTS는 유지한다.
2. 공식 실물 → 동일 형태 디오라마 기준 이미지 검수 → Flow 참조 자산을 먼저 확정한다.
3. `prompt_check.py`와 `build_hybrid_flow_pack.py`의 생성 게이트를 통과시킨다.
   별도 확장 TXT는 `python tools/diorama_style_check.py 이미지.txt 영상.txt --expected-count N`으로 검사한다.
4. 9:16·배치 고정 길이·결과1·동시작업1을 화면에서 확인. 실제 참조 칩·시작 이미지 파일과 미리보기를 확인한다.
5. 이미지 전수 검수 후 같은 번호의 I2V만 실행. 시작/끝 모드의 파일 짝짓기는 1건 확인 후 확대한다.
6. `PENDING → SUBMITTED → GENERATING → DOWNLOADED → QA_PASS`를 구분한다.
   연결이 끊기면 같은 작업의 기존 결과부터 확인하고 중복 재전송하지 않는다.
7. 텍스트 검사 통과는 시각 검사 통과가 아니다. 얼굴·유물 형태·컷 의미·리셋을 결과에서 검사한다.

확장을 삭제·재설치하거나 다른 연결을 끊는 것은 별도 승인 없이는 하지 않는다. 단계 시작·첫 성공·오류·마지막에
화면을 확인하고, 같은 대기 상태마다 전체 화면을 반복 읽지 않는다. 실패 컷을 다른 컷으로 돌려막지 않는다.

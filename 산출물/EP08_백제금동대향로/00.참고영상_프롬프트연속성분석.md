# 참고 영상 프롬프트 연속성 분석

분석일: 2026-08-30

이 문서는 완성 영상을 수정하기 위한 문서가 아니다. 이미 생성된 실패 사례와 당시 저장된
영상 프롬프트를 대조해 다음 회차의 프롬프트 작성 규칙을 고치기 위한 기록이다.

## 사례 A — 동굴·항아리·두루마리

- 파일: `Camera_moving_through_cave_artifact_202608302051.mp4`
- 규격: 10.005초, 720×1280, 24fps, 240프레임
- 관찰: 동굴 전경에서 항아리와 두루마리를 지나 글자 매크로까지 이동한 뒤, **6.125초에
  시작 동굴 구도로 하드컷처럼 복귀**해 이동을 다시 시작한다.
- FFmpeg 장면 변화 점수: 31.615 at 6.125s
- 결론: 재생기·다운로드·CapCut 문제가 아니라 생성 원본에 들어간 공간 리셋이다.

대응되는 EP07 마지막 장면 프롬프트는 한 10초 클립에 다음을 모두 요구했다.

1. 동굴 입구 진입
2. 항아리와 두루마리 반원 회전
3. 잉크 섬유까지 극단 매크로 푸시인
4. 다시 천천히 풀백

`push into ... then pull back`은 진행 방향과 화면 규모를 되돌리는 두 번째 카메라 동작이다.
모델은 약 6초에 매크로 도착까지 완료한 뒤 물리적 후진을 이어가지 못하고 시작 이미지를
새 쇼트처럼 재사용했다.

## 사례 B — 사해 절벽

- 파일: `Camera_moving_along_Dead_Sea_202608300510.mp4`
- 규격: 8.000초, 720×1280, 24fps, 192프레임
- 관찰: 높은 항공 전경을 유지하다 약 1.5초 부근에서 지상 협곡 카메라로 갑자기 바뀐다.
  색과 재질이 비슷해 하드컷 검출 임계값 15에는 잡히지 않지만, 카메라 위치와 고도가
  연속된 물리 경로 없이 바뀌는 기하학적 점프다.

당시 장면 003 프롬프트는 실제 시작 이미지가 높은 항공 전경인데도 다음을 요구했다.

1. 해안의 소금 결정에서 시작
2. 협곡을 저공으로 급상승
3. 동굴 입구 세 곳을 가로질러 횡이동
4. 깊은 저장 선반에서 종료

`entry_anchor`인 소금 결정은 선택된 실제 첫 프레임에서 보이지 않았다. 프롬프트의
`Begin within 0.35 seconds`까지 겹쳐 모델은 첫 1~2초 안에 새로운 지상 카메라 위치를
재합성했다. `SECTION_DIVE`도 단면이 아닌 외부 절벽 장면에 잘못 배정돼 있었다.

## 확정 원인

두 사례의 공통 원인은 `no hard cut` 문구 누락이 아니다. 두 프롬프트 모두 이미
`Single continuous ... no hard cut`을 포함했다. 실제 원인은 다음 네 가지다.

1. 한 클립에 카메라 행동이 둘 이상 들어감
2. WIDE→MACRO 또는 항공→지상처럼 화면 규모·고도가 크게 바뀜
3. 선택된 실제 첫 프레임에 없는 시작 앵커를 지시함
4. TTS 비트만 있고 0초·중간·마지막의 실제 화면 상태를 잠그지 않음

## 다음 생성부터의 규칙

- 한 클립은 **주 행동 1개 + 카메라 행동 1개 + 환경 반응 1개**만 가진다.
- 8~10초는 한 공간·한 진행축·한 화면 규모·한 도착점만 허용한다.
- `push in then pull back`, `rise then dive`, `orbit then enter`는 두 클립으로 나눈다.
- 선택된 실제 시작 이미지에서 보이지 않는 `entry_anchor`는 폐기한다.
- 4/6/8/10초 장면은 각각 2/3/3/4개의 `visual_states`를 먼저 잠근다.
- 긴 장면은 Start/Mid/Final anchor와 마지막 프레임 유지, reset/loop/restart 금지를 적는다.
- 복잡한 이동은 4~6초로 나누고 앞 클립 마지막 선명 프레임을 다음 I2V 시작점으로 쓴다.
